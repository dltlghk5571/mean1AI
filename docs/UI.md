# 시민·업무 화면 사용성과 검증

## 시민 접수 화면

`/`는 시민 메인, `/staff`는 담당자 업무 홈입니다. 시민 화면은 별도의 `citizen_base.html`,
`citizen.css`, `citizen.js`를 사용합니다. 초록색 주요 동작, 생활 분야 카드, 로컬 SVG 동네
일러스트를 사용하며 외부 폰트·이미지·라이브러리를 요청하지 않습니다.

- `/minwon/new`: 시연 챗봇 → 목적 선택 → 내용·장소 질문 → 요약 수정 → 필수 안내 확인 → 접수.
  주어진 글의 의도를 키워드로 분류하지 않고 사용자가 목적을 고릅니다. `citizen-chat.css/js`를
  별도로 사용하며, 정보 분기에서는 검색 미연결 안내와 공식 사이트 링크를 제공합니다.
- `/minwon/form`: 제목·선택 장소·내용 작성 → 비식별 미리보기 → 필수 데모 안내 확인 → 접수.
- `/minwon/{id}/receipt`: 실제 저장 성공 뒤 접수번호·조회 코드·접수 시각 표시. 코드 복사와
  민원 상세 이동을 제공합니다. 소유 세션에서는 같은 코드를 다시 확인할 수 있습니다.
- `/minwon/lookup`: 현재 세션의 접수·조회 권한 목록과 접수번호/코드 입력 양식.
- `/minwon/{id}`: 비식별 접수 내용과 `접수 완료 / 확인 중 / 답변 등록` 상태, 명시적으로
  공개한 답변만 표시합니다. 내부 부서 후보·초안·담당자 계정·감사 기록은 전달하지 않습니다.
- 서버 검증 오류는 항목별 문구와 알림으로 표시합니다. 미리보기·접수·조회 실패에도 현재
  입력은 유지합니다. 처리 중 버튼을 막고, 동일 요청 식별자의 재시도는 기존 접수로 연결합니다.
- URL·localStorage·sessionStorage에 작성 내용을 저장하지 않습니다. 챗봇은 전송한 대화를
  서버에서 식별자 형식을 가려 저장하며 새로고침으로 이어볼 수 있습니다. 직접 작성 양식은
  페이지 메모리에만 유지하고 미리보기는 원문을 수정하지 않습니다. 원문은 최종 접수 때 저장합니다.
- 단계 변경 시 제목으로 포커스를 이동하고 숨긴 단계는 키보드 탐색에서 제외합니다. 모바일
  입력란은 16px로 표시합니다. 키보드 포커스·본문 바로가기·동작 줄이기를 지원합니다.
- 작성·조회에는 JavaScript가 필요하며 비활성화된 경우 안내합니다. 민원 목록·상세는 서버 렌더링입니다.
- 담당자 상세의 `시민에게 답변 공개` 패널은 검토 승인 역할에만 공개 폼을 제공합니다.
  화면에 표시된 검토 버전과 확인 체크박스를 서버에서 다시 검증합니다.

시민 흐름 수동 검증: 빈 양식 제출 → 합성 예시 → 식별자 형식 마스킹 확인 → 수정 복귀 →
데모 안내 확인 → 접수 → 코드 복사 → 내 민원 조회. 담당자 내부 승인 후 아직 비공개인지
확인하고, 명시적 공개 후 시민 상세를 새로고침합니다. 320px·375px 모바일와 데스크톱에서
가로 넘침과 동작 버튼 잘림을 확인합니다. 접근 경계·트랜잭션·이력 검증은 `tests/test_citizen.py`입니다.

챗봇 검증: 자유 입력 → 목적 선택 → 장소 입력/모름 → 요약 수정 → 동의 → 접수 결과.
정보 안내만으로 민원이 생성되지 않는지, 새로고침·새 대화·다른 탭 충돌·통신 실패·재시도를
확인합니다. API 검증은 `tests/test_citizen_chat.py`입니다. 실제 사진·음성·모델 추론은 미연결입니다.
한글 조합 중 Enter 전송을 막고 Shift+Enter로 줄바꿈합니다. 낭독기는 전체 대화 대신 최신 응답을
알리고, 최종 확인 단계에서는 제목으로 초점을 옮깁니다. 대화 원문은 HTML로 해석하지 않습니다.

## 화면 구성

로그인·대시보드·상세·접수 창은 밝은 회색 바탕, 흰색 패널과 청록색 주요 동작을 공유합니다.
검토 필요 지표에는 연한 녹색을, 긴급 상태에는 적색과 상태 문구를 함께 사용합니다.
모든 집계는 기존 서버 통계이며, 시각 효과를 위한 가상 수치나 추세는 추가하지 않습니다.

- 대시보드는 큰 상태별 건수 → 확인 필요 안내 → 최근 민원 목록 순서로 구성합니다.
  목록의 검색·정렬과 상태 필터를 모으고, 접수 버튼은 페이지 제목 옆에 한 번 표시합니다.
- 넓은 화면에서는 검토 단계 가이드와 처리 원칙을 목록 옆에 표시합니다. 1150px 이하에서는
  안내를 목록 아래로 이동하고, 상태별 의미는 ‘민원 상태 안내’를 펼쳐 확인합니다.
- 상세 화면은 접수 내용과 검토 패널을 나란히 배치하고, 1150px 이하에서는 세로로 배치합니다.
  긴 민원 본문·후보 설명·지식 문서 ID는 줄바꿈하고, 상세 구간 메뉴는 상단에 고정합니다.
- 로그인은 업무 흐름 안내와 인증 양식을 분리합니다. 시연 계정과 권한 검사는 그대로 유지합니다.
- 접수 창은 헤더·처리 단계·하단 버튼의 실제 높이에 맞춰 남은 공간에 입력 영역을 배치합니다.
  입력 영역만 스크롤되므로 좁거나 낮은 화면에서도 ‘안전 분석 시작’ 버튼이 잘리지 않습니다.
- 외부 폰트·이미지·라이브러리는 추가하지 않았습니다. 시스템 한글 폰트와 SVG 아이콘을 사용하고,
  키보드 포커스·동작 줄이기 설정·모바일 메뉴의 기존 포커스 관리를 유지합니다.

## 목록

- 상태 필터는 서버가 선택한 상태의 최근 30건을 불러옵니다. 전체 접수 통계는 전체 DB 기준입니다.
- 검색과 정렬은 현재 불러온 목록에만 적용합니다. `0 / 11건`은 현재 목록 11건에서 일치하는
  항목이 없다는 뜻이며, 이전 접수 건까지 DB 전체를 검색했다는 뜻이 아닙니다.
- 검색 범위는 비식별 제목·위치·분야·세부 유형입니다. Unicode NFKC, 소문자 변환 후 공백으로
  나눈 검색어가 모두 포함되는 행만 표시합니다. 민원 원문이나 추가 개인정보를 요청하지 않습니다.
- 기본 정렬은 서버의 최신 접수순입니다. 오래된순은 그 역순이고, 검토 우선순은 긴급 검토 →
  검토 대기 → 접수됨 → 배정 완료 → 검토 완료입니다. 같은 상태는 최신순을 유지합니다.
- `/`는 입력란·선택 상자·편집 영역·열린 대화상자 밖에서 검색창으로 이동합니다.
  검색창의 `Esc`, 지우기 버튼, 검색 초기화 버튼은 검색어만 지우고 현재 정렬은 유지합니다.
- 검색어는 메모리에만 존재합니다. URL, localStorage, sessionStorage, 서버에 기록하지 않습니다.
- 검색 결과가 없는 행은 native `hidden` 상태를 CSS에서도 보장해 화면과 키보드 탐색에서 제외합니다.
  표시 건수는 스크린 리더에도 짧은 지연 후 전달됩니다.

## 상세와 모바일

선택한 OpenAI 지연 처리 모드에서는 목록과 상세에 AI 분석 대기·분석 중·완료·실패를 민원 업무
상태와 별도로 표시합니다. 상세에는 시도 횟수, 최대 횟수, 상태 새로고침 링크가 있습니다.
대기·처리 중에는 다시 분석 버튼을 비활성화하지만 담당자 검토는 가능합니다. 승인하면 활성
AI 작업을 종료하고 그 결과가 나중에 반영되지 않게 합니다. 실패한 민원도 사람 검토를 계속할 수
있습니다. 규칙 처리와 긴급·민감 사전 확인은 즉시 실행되며, UI 갱신은 일반 페이지 새로고침으로
수행합니다. 감사 조회 역할에는 분석·승인 폼을 제공하지 않습니다.

상세 구간 링크는 일반 URL fragment 이동입니다. JavaScript가 없어도 이동할 수 있고 고정 메뉴가
본문을 가리지 않도록 여백을 둡니다. 업무분장 버전, 분류 근거와 후보 설명은 줄바꿈해 읽을 수
있습니다. 후보 선택은 검토 승인 역할에서만 가능하며 `aria-pressed`로 선택 상태를 알립니다.

적용 중인 안전 기준은 설명 목록으로 표시합니다. 담당자가 실제로 확인하지 않은 체크박스를
미리 체크하지 않습니다. 내부 승인 전 확인 대화상자, 역할 검증, 개인정보 검사, 감사 이력은
기존 서버 절차를 그대로 사용합니다. 행정 결정·종결·발송 기능은 없습니다.

900px 이하에서는 모바일 메뉴를 사용합니다. 닫힌 메뉴는 `inert`, 열린 동안 본문은 `inert`로
설정합니다. Tab과 Shift+Tab은 메뉴 안에서 순환하며 Esc/닫기 후 열기 버튼으로 포커스를
돌려줍니다. 900px를 넘나들면 메뉴 상태를 초기화합니다.

## 정확한 검증 명령

저장소 루트의 PowerShell에서 실행합니다.

```powershell
$env:AI_PROVIDER='rules'
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m ruff format --check .
.venv\Scripts\python.exe -m mypy app evals tests
.venv\Scripts\python.exe -m pytest
node --check app/static/app.js
node --check app/static/citizen.js
node --check app/static/citizen-chat.js
git diff --check
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

업무 브라우저 검증은 `http://127.0.0.1:8765/staff`에서 합성 계정과 합성 민원만 사용합니다.

1. 기존 합성 목록에서 존재하지 않는 검색어를 입력합니다. 건수가 0이고 행은 화면과 키보드
   탐색에서 사라져야 합니다. 초기화 후 같은 개수의 행이 복원되고 검색창이 포커스를 받습니다.
2. `가로등`을 검색해 일치하는 제목·위치·분야만 남는지 봅니다. 필터 상태에서 오래된순으로
   바꾸면 현재 결과만 역순이어야 합니다. Esc로 지운 뒤에도 정렬은 유지되어야 합니다.
3. 입력란 밖에서 `/`로 검색창에 이동합니다. 선택 상자, 답변 초안, 열린 모달에서 `/`를
   입력해도 검색창으로 포커스를 빼앗기지 않아야 합니다.
4. 390×844, 768×900, 1024×900, 기본 데스크톱에서 목록과 상세의 가로 넘침이 없는지 확인합니다.
   상세 구간 링크로 이동한 본문 제목이 고정 메뉴 아래에서 보여야 합니다.
5. 모바일 메뉴 열기 → Shift+Tab/Tab 순환 → Esc를 확인합니다. 닫힌 메뉴에 보이지 않는
   포커스가 들어가거나, 열린 메뉴 뒤 본문으로 포커스가 빠지면 실패입니다.
6. 합성 예시 입력, 취소, 답변 미리보기, 후보 선택 후 승인 확인창에서 취소를 확인합니다.
   단순한 미리보기·후보 선택·취소는 서버 기록을 변경하지 않아야 합니다.
7. 감사 조회 계정은 후보 버튼과 초안 수정·승인을 사용할 수 없어야 합니다. 브라우저 console에
   오류가 없어야 합니다. 마지막으로 임시 viewport 변경을 해제합니다.

이 절차는 로컬 화면 회귀 확인이며, 공식 접근성 인증이나 보조기기 전체 조합 검증은 아닙니다.

## 시민 에이전트 자료 카드 검증

`CHAT_PROVIDER=agent_demo`와 별도 로컬 DB에서 [데이터 검수 절차](SERVICE_DATA_PIPELINE.md)의
합성 업무를 등록·승인한 뒤 `/minwon/new`를 연다.

1. `가로등` 입력 후 `복지·생활정보 알아보기`를 선택하면 해당 합성 안내 카드가 나타난다.
   제목·설명·출처·재검수 예정일과 시연용 표시를 확인한다. 합성 자료에는 공식 원문 링크가 없다.
2. 새로고침해 대화와 카드를 이어 볼 수 있는지 확인한다. 320px와 1280px에서 가로 넘침이
   없어야 하며 검색 자료 영역은 접근 가능한 이름을 가진 section으로 제공한다.
3. 자료가 없으면 공식 사이트 안내로 전환한다. 자료 승인·철회는 담당자 API에서만 가능하다.
   철회·만료·교체된 자료는 다음 대화 요청/이어보기에서 제외하며 열린 화면을 강제로 갱신하지 않는다.
4. `민원으로 접수할게요`를 선택해 내용·장소 질문과 요약 확인으로 진행한다. 카드 조회만으로
   민원이 생기지 않고, 시민의 최종 동의가 있어야 접수된다.

2026-09-06 로컬 브라우저에서 합성 자료 검색, 출처 카드, 새로고침 후 이어보기,
320px·1280px 가로 넘침 없음과 콘솔 오류 없음을 확인했다. 자료 철회·접수 경계·실패 롤백은
`tests/test_citizen_agent.py`와 기존 시민 채팅 테스트에서 검증한다.

## 안내 자료 검수 화면 검증

`/staff/service-catalogs`에서 검수 권한이 있는 합성 계정으로 확인한다.

1. 성남시 조사 후보 12개를 불러오면 미리보기만 표시되고, `검수 대기로 등록`을 눌러야
   버전이 저장된다. 원문 링크·수동 요약·분류·조직 경로와 확인되지 않은 항목을 확인한다.
