# 자유 입력 정리 제안과 사용자 확인

2026-09-12 · 추출 계약 v1 · 기존 대화 계획 계약 v2 유지

처음 적은 문장에서 원하는 도움·상황·장소·추가 질문 답변을 제안하고, **시민이 확인한 뒤**
초안에 반영한다. 확인 화면은 최종 접수와 별개다. 본문·사진을 확인하고 마지막 접수 동의까지
해야 시제품 민원이 저장된다. 실제 동아리 LLM과 기관 접수는 아직 연결하지 않았다.

## 시민 흐름

1. 시작·목적 선택·정보 안내 화면에서 새 이야기를 적는다. 설정된 추출기가 있으면
   비식별 원문과 앱의 질문 묶음을 전달한다. 이미 직접 선택한 상황의 질문·장소 입력에는
   추출기를 끼워 넣지 않아 명시한 선택과 답변을 다시 바꾸지 않는다.
2. 유효한 제안은 **이렇게 이해했어요** 카드에 보여 준다. 원하는 도움, 상황, 장소와 아는 답변,
   각 항목의 **내가 쓴 표현 보기**를 제공한다. 이때 본문은 시민이 적은 그대로이고,
   제안한 장소·상황·답변은 아직 초안에 반영하지 않는다.
3. **맞아요, 이 내용으로 계속**을 누르면 제안한 목적·상황·장소를 적용한다.
   원문에서 확인한 답변은 `in_description`과 해당 문구로 기록해 같은 질문을 반복하지 않는다.
   원문에 답변이 있으므로 접수 본문 뒤에 중복해서 붙이지 않는다. 부족한 항목만 기존 흐름으로 묻는다.
4. **직접 선택할게요**를 누르면 제안을 버리고 기존 목적 선택으로 이어간다. 원문은 보존한다.
   확인 후에도 마지막 요약에서 내용·장소·추가 답변을 수정할 수 있다. 본문을 수정해 확인한
   문구가 사라지면 그 추출 답변을 지우고 다시 물으며, 직접 건너뛴 답변은 유지한다.
5. 정보 안내 목적은 안내로 끝난다. 이후 **민원으로 접수할게요**와 최종 동의가 있어야
   민원을 만든다. 복지 질문 묶음의 사람 검토 규칙도 계속 적용한다.

여러 문제가 섞이거나 목적이 모호하면 모델은 보류를 반환해야 한다. 보류·통신 장애·잘못된
응답은 제안을 적용하지 않고 원문과 직접 선택 경로를 유지한다. 화면에 자동 정리 실패 또는
직접 선택 안내를 표시한다. 다른 모델의 성공 응답이나 합성 판단으로 대신하지 않는다.
긴급 신호는 모델을 기다리지 않고 기존 긴급 안내와 직접 선택을 제공한다.

## 앱 설정

기본값은 `CHAT_EXTRACTION_PROVIDER=off`다. 기존 시민 흐름은 계속 사용할 수 있다.
실제 서버 준비 뒤 앱의 커밋하지 않는 `.env`에 아래 예시를 설정한다.

```dotenv
CHAT_EXTRACTION_PROVIDER=club
CHAT_EXTRACTION_ENDPOINT_URL=https://models.example.test/v1/agent/extract
CHAT_MODEL_ID=your-reviewed-agent-version
CHAT_API_KEY=replace-outside-git
CHAT_REQUEST_TIMEOUT_SECONDS=15
CHAT_MAX_CONCURRENT=4
```

추출은 **대화 모델의 별도 작업**이며 새 모델을 하나 더 학습할 필요가 없다. `CHAT_MODEL_ID`와
`CHAT_API_KEY`를 공유하되, 추출 URL과 켜기/끄기는 대화 계획의 `CHAT_PROVIDER`와 독립적이다.
대화 계획까지 연결할 때는 기존 `CHAT_ENDPOINT_URL`을 `/v1/agent/plan`으로 설정한다.
접수 후 부서 분류의 `AI_PROVIDER`도 별도로 유지한다.

원격 HTTPS, 로컬 시험의 `localhost`·`127.0.0.1`·`::1` HTTP만 허용하며 URL의 인증정보·쿼리·
fragment는 거부한다. `club`에는 주소·모델 ID·Bearer 키가 모두 필요하다. 앱이 추출 서버를
자동 시작하지 않는다. 게이트웨이 백엔드의 `extract()`에 실제 추론 구현을 주입해야 한다.

### 실제 모델 없는 합성 시연

`CHAT_EXTRACTION_PROVIDER=demo`에서는 시작 화면의 **합성 예시 넣어 보기**로 아래 문장을
입력할 수 있다. 버튼은 입력란만 채우며 사용자가 전송한다.

> 합성 별빛공원 동문 앞 가로등이 어제 저녁부터 꺼져 있어요. 수리를 요청하고 싶어요.

이 문장에만 고정된 정리 결과를 반환하며 카드에 합성 예시라고 표시한다. 다른 문장은
보류하고 직접 선택으로 이어간다. 키워드 분류·실제 LLM 추론·정확도 시연이 아니다.
게이트웨이 `synthetic`의 추출 경로도 동일한 예시를 제공한다. 앱의 `club` 연결부는 합성 응답을
거부하므로 게이트웨이 합성 응답은 계약 시험용이고 UI 시연은 명시적인 로컬 `demo`를 사용한다.

이번 구현에서는 로컬 웹·모델·MCP 서버를 시작하지 않았다. 내부 ASGI/MockTransport 테스트와
모든 HTTP 요청을 내부 TestClient로 처리한 Chromium에서 확인 카드·키보드·모바일 200%를
검사했다. CI에서는 전체 회귀 검사와 격리된 브라우저 검사를 수행한다.

## 모델 팀의 JSON 계약

- [요청 Schema](contracts/intake-extraction-request.schema.json)
- [응답 Schema](contracts/intake-extraction-response.schema.json)
- 원본 `app/extraction_schemas.py`; 공개 Schema 일치를 테스트한다.
- 경로 `POST /v1/agent/extract`; JSON 객체 하나, 스트리밍·Markdown 제외.

요청은 `schema_version="1"`, `task="extract_intake"`, 호출별 `request_id`, `input_hash`,
대화 `model_id`, `source_text`, 허용 `templates` 목록이다. 현재 원문 최대 4,000자와 질문 묶음
12개의 ID·버전·문구·항목을 전달한다. 시민/민원 ID·세션·쿠키·조회 코드·사진·다른 사람의 글·
이전 도우미 답변은 보내지 않는다. 직접 식별자 형식은 원문에서 다시 가린다.

`input_hash`는 `input_fingerprint()`로 원문과 질문 목록 전체의 정규화 JSON을 SHA-256으로
계산한다. 응답은 `schema_version`, `request_id`, `input_hash`, `model_id`, `execution_mode`와
아래 `proposal`을 포함한다. 요청 ID·해시·모델 ID·실행 모드가 맞지 않으면 거부한다.

```json
{
  "abstained": false,
  "reason": "supported",
  "purpose": {"value": "complaint", "quote": "수리를 요청하고 싶어요."},
  "topic": {"template_id": "lighting", "quote": "가로등이"},
  "location": {"value": "합성 별빛공원 동문 앞", "quote": "합성 별빛공원 동문 앞"},
  "answers": [{"field_id": "observed_time", "value": "어제 저녁부터", "quote": "어제 저녁부터"}]
}
```

위 코드는 합성 응답의 `proposal` 부분이다. `purpose`는 `complaint` 또는 `information`이고
유효한 제안에는 필수다. 상황·장소는 모르면 null, 아는 추가 답변만 최대 4개 넣는다.
보류할 때는 `abstained=true`, 목적·상황·장소 모두 null, 빈 답변 목록으로 반환하고 이유는
`ambiguous`, `multiple_issues`, `insufficient_information` 중 하나다.

모든 `quote`는 원문의 정확한 부분 문자열이어야 한다. 장소와 답변의 `value`는 quote와
동일해야 하므로 주소 완성·좌표 추정·날짜 변환·사실 요약을 임의로 하지 않는다. 상황 ID와
답변 ID는 전달받은 목록만 사용한다. 중복·미등록 항목, 길이 초과, 추가 필드, 식별자와
식별자 마스킹 표식을 값으로 제안한 응답을 거부한다. `choices_only` 안전 질문은 추출로
답하지 않고 시민에게 명시적인 선택을 요청한다. 정확한 인용 검사만으로 의미상 올바른
분류가 증명되지는 않으므로 시민 확인과 실제 모델 평가가 모두 필요하다.

## 확인 API·일관성·감사

기존 `/minwon/chat/turn`의 문자열 JSON·같은 시민 세션·CSRF·revision·request_id를 재사용한다.
`accept_extraction` 또는 `dismiss_extraction`에 `extraction_id` 문자열만 추가한다. 앱이 저장한
제안을 선택하는 ID이며 클라이언트는 값·목적·상황·답변 사전을 덮어쓸 수 없다.

```json
{
  "revision": "1",
  "request_id": "b6b13111-fd52-4fd9-8d64-09bf541290aa",
  "action": "accept_extraction",
  "extraction_id": "579a5fa0-2caa-4d21-a9ea-c8a32568c900"
}
```

ID는 설명용이다. 실제로 받은 현재 카드 ID를 사용한다. 확인 대기 중에는 적용·직접 선택·
새 대화 외 변경과 최종 접수를 막는다. 같은 성공 요청의 재전송은 모델 재호출이나 중복
적용 없이 현재 결과를 반환한다. 원문·모델·제공자·질문 목록이 달라지면 적용을 거부하고,
이어보기에서도 오래된 카드의 적용 버튼을 비활성화한다. 직접 선택과 새 대화는 가능하다.

모델 호출 전 `extraction_requested` 감사를 커밋하고 DB 트랜잭션을 닫는다. 요청 중 다른
대화가 먼저 반영되면 CAS로 결과를 폐기한다. 제안 저장과 적용·거절은 각각 상태 변경과
`extraction_resolved` 감사를 함께 커밋한다. 경합·실패로 반영하지 못하면 `extraction_aborted`를
남긴다. 감사 실패 시 제안·초안 변경을 롤백한다. 감사에는 고정 상태, 요청 ID, 모델/제공자,
입력 해시와 시민 확인 여부만 넣고 원문·값·인용·키·URL·예외 내용은 복사하지 않는다.

미접수 제안은 기존 개인 대화 상태 JSON에 저장한다. 별도 DB 테이블이나 운영 마이그레이션은
없으며, 기존 대화는 새 선택 필드의 기본값으로 읽는다. UI는 모델 문구를 HTML로 실행하지 않고
textContent로 표시하며 키보드 초점·모바일 폭·글자 200%를 검사한다.

## 한도와 다음 작업

요청 80,000바이트·응답 12,000바이트, HTTP 전체 기한 최대 15초, 앱과 게이트웨이 각각의
프로세스당 동시성 제한을 적용한다. 앱은 `CHAT_MAX_CONCURRENT`의 최대 4개까지 사용하며,
총 HTTP 시간은 `CHAT_REQUEST_TIMEOUT_SECONDS`와 15초 중 작은 값이다. TLS 검증을 유지하고
리다이렉트·환경 프록시·압축·HTTP 재시도는 사용하지 않는다. 임의의 동기 GPU 연산을
강제로 중단하는 기능은 아니며 실제 엔진의 취소·용량은 서버 준비 뒤 검증한다.

모델 담당자는 문맥이 모호한 사례·복합 민원·부정문·원문 없는 항목·PII·오류 사례의 실제
예측을 평가해야 한다. 현재 합성 시험을 모델 성능으로 보고하지 않는다. 이미 선택한 상황의
진행 중 답변 추출, 혼합 민원 분해, 제안 일부만 선택 적용, 자유 요약·날짜/주소 정규화는
후속 범위다. 추가 질문의 현행 수동 수정과 최종 동의는 계속 앱이 관리한다.
