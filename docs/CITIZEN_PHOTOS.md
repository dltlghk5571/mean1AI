# 시민 사진 첨부

2026-09-07 · AI 서버 없이 동작하는 시연 기능

`/minwon/new`의 접수 확인 단계에서 사진을 선택·미리보기·삭제할 수 있다. 사진은 선택만으로
전송되지 않고 현재 페이지의 메모리에 남는다. 새로고침·탭 닫기는 선택한 사진을 지운다.
최종 동의 후 접수 버튼을 누르면 민원과 사진을 한 트랜잭션으로 저장한다. 사진 없이도 접수할 수 있다.

접수 확인서는 사진 개수를 보여주고, 시민 상세와 담당자 상세에서 사진을 크게 볼 수 있다.
사진을 추가·삭제하면 최종 동의 체크가 풀려 변경된 내용을 다시 확인하게 한다.

## 파일 처리와 권한

- JPG·PNG 최대 3장, 원본 한 장당 5,000,000바이트·16,000,000화소. 애니메이션은 받지 않는다.
- 실제 디코딩 형식과 선언한 MIME이 일치해야 한다. 손상된 파일·SVG·잘못된 base64는 거부한다.
- 촬영 방향을 적용한 뒤 긴 변 최대 1,600px로 줄이고 새 RGB 캔버스에 JPEG로 다시 저장한다.
  저장본은 한 장당 최대 2,000,000바이트다. 원본 파일명·EXIF·GPS·ICC·PNG 텍스트는 보관하지 않는다.
- **사진 속 얼굴·차량번호·문자는 자동으로 가리지 않는다.** 개인정보가 없는 합성 시연 사진만 사용한다.
  사진·파일명은 대화 상태, 모델 입력, 감사 본문이나 로그에 넣지 않는다. 사진 AI 판독·OCR은 미구현이다.
- 시민 이미지 조회는 유효한 본인 세션 또는 해당 민원 조회 코드로 얻은 접근 권한이 필요하다.
  다른 시민·만료 세션·다른 민원 경로로는 조회할 수 없다. 담당자는 기존 로그인 범위에서 확인한다.
- 이미지 응답은 `image/jpeg`, `no-store`, `nosniff`, 동일 출처 자원 정책을 사용한다.
  외부에 공개하는 정적 파일 URL이나 제3자 저장소는 없다.

이미지 처리는 [Pillow Image](https://pillow.readthedocs.io/en/stable/reference/Image.html)와
[ImageOps](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html)의 디코딩·방향 처리 기능을
사용한다. `Pillow>=12.3,<13`을 실행 의존성에 추가했다.

## HTTP 계약

| 경로 | 동작 |
| --- | --- |
| `POST /minwon/chat/confirm-with-photos` | 시민 세션·CSRF·초안 버전·최종 동의 확인 후 민원과 사진 저장 |
| `GET /minwon/{complaint_id}/photos/{photo_id}` | 해당 민원 조회 권한이 있는 시민에게 사진 반환 |
| `GET /api/v1/complaints/{complaint_id}/photos/{photo_id}` | 로그인한 담당자에게 사진 반환 |

사진 없는 접수는 기존 `POST /minwon/chat/turn`을 그대로 사용한다. 사진 첨부는 별도 JSON
봉투로 전송하며 아래 `data`는 데이터 URL 접두사 없는 파일 바이트의 base64다. UUID와 데이터는 예시다.

```json
{
  "turn": {
    "revision": "3",
    "request_id": "00000000-0000-4000-8000-000000000001",
    "action": "confirm",
    "consent": "yes"
  },
  "photos": [{"media_type": "image/png", "data": "파일 바이트의 base64"}]
}
```

성공 응답은 기존 대화 상태와 접수 확인서 `redirect`다. 모델 서버의 JSON 계약에는 사진을 추가하지 않는다.
`request_id`와 원본 사진 해시·순서까지 확인하므로 같은 요청의 재시도는 한 번만 저장되고,
같은 요청 ID에서 사진을 바꾸면 409다. 실패하면 민원·사진·접수 감사 기록이 함께 롤백된다.

요청 본문은 스트리밍 중 20,050,000바이트 제한을 검사하며 수신에 20초 제한을 적용한다.
사진 접수는 프로세스당 동시 2개, 기존 접수와 공유하는 IP당 분당 5회 제한을 사용한다.
이 수신 시간 제한은 디코더나 후속 분류기의 전체 실행 시간을 강제로 제한하는 기능은 아니다.
브라우저는 전송 실패 시 선택한 사진과 동일한 요청을 유지해 재시도할 수 있다.

## 저장과 후속 작업

`citizen_photos` 추가 테이블에 접수 ID, 순서, 크기, 저장본 해시와 JPEG 바이트를 보관한다.
기존 테이블을 바꾸지 않아 기존 SQLite DB도 앱 시작 시 추가 테이블을 생성할 수 있다.
DB 트랜잭션에 포함하므로 실패 시 별도 파일 정리 작업이 필요하지 않다. 감사에는 사진 ID만 연결한다.
접수 전 서버 임시 사진, 공개 파일 디렉터리, 백그라운드 업로드 작업은 만들지 않는다.

세션 만료는 접근 만료이며 저장된 사진의 자동 삭제가 아니다. 운영 보존·삭제 정책, 대용량 저장소,
문서 첨부, HEIC·WebP 지원, 사진 속 식별정보 검토와 OCR/비전 모델 연결은 후속 작업이다.
직접 작성 화면 `/minwon/form`은 기존 텍스트 접수를 유지한다.
