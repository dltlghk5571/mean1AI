# 성남시 + 경기도·전국 민원·복지 분류 및 수집 출처

확인일: 2026-09-05 · 용도: 연구·설계용 초기 목록 · 실제 앱 분류표 반영 전

이 문서의 부서명은 표시된 공식 출처를 조사한 값이다. 현재 앱의 합성 부서 카탈로그와 별도이며,
시청이 우리 서비스의 배정 규칙을 승인했다는 의미는 아니다. 전체 상세 분류·부서·관할 대응표는
수집과 검수가 끝난 뒤 확정한다.

## 1. 몇 종류의 민원이 있는가

하나의 숫자로 표현하기 전에 서로 다른 목록을 나눠야 한다.

| 목록 | 이번 확인 | 의미 |
| --- | --- | --- |
| 성남시 민원/제안/신고의 서비스 유형 | 7개 | 문의·신고·제안 등 창구 탐색 필터 |
| 같은 화면의 분야 | 8개 | 생활·행정 주제 필터 |

| 성남시 민원 편람의 분야 | 13개 | 증명·허가·신고 등을 찾아보는 분류 |

분야와 부서는 다대다 관계를 허용한다. 공공데이터포털의 ‘사회복지 - 사회복지일반’ 같은
데이터셋 메타 분류를 민원 세부 코드로 착각하지 않는다.

복지로와 공공서비스 API의 같은 사업은 기관명·사업명만으로 덮어쓰지 않는다. 원본 서비스 ID를
각각 보존하고 동일 사업 여부·적용 연도·지원 지역을 검수한다. 전국·경기도·성남시·구별 범위를
구분해 시민에게 적용되지 않는 타 지자체 혜택이 섞이지 않게 한다.

### 확인한 지자체 복지 API 명세

- Base path: `apis.data.go.kr/B554287/LocalGovernmentWelfareInformations`
- `GET /LcgvWelfarelist`: 목록 조회.
- `GET /LcgvWelfaredetailed`: 상세 조회.
- 목록 조건에 `ctpvNm`(시도명), `sggNm`(시군구명), `lifeArray`(생애주기),
  `trgterIndvdlArray`(가구상황), `intrsThemaArray`(관심주제), `pageNo`, `numOfRows` 등이 있다.
- 응답 명세에서 `servId`, `servNm`, `servDgst`, `servDtlLink`, `bizChrDeptNm`, `lastModYmd`
  등을 확인했다. 실제 지역명·코드 허용값은 첨부 코드표와 호출 결과로 검증한다.
- 단순 서비스 검색에 시민의 이름·연락처·주민번호를 보내지 않는다. 민감한 조건은 최소화하고
  가능하면 서버에 미리 동기화한 공개 정보에서 검색한다.

근거: [공식 Swagger 및 코드표 안내](https://www.data.go.kr/data/15108347/openapi.do),
[공식 메타데이터](https://www.data.go.kr/catalog/15108347/openapi.json).

## 4. 수집 작업을 나누는 방법

| 수집 묶음 | 원천 | 추출할 항목 | 책임 |
| --- | --- | --- | --- |
| 서비스 목록 | 성남시 민원/제안/신고의 5페이지 | 제목·유형·분야·담당 표시·상세 URL·원본 ID | C 수집, A 검수 |
| 민원 편람 | 목록·상세·첨부 서식 | 업무명·분류·부서·대상·서류·방법·기한·수수료·근거 | C 수집, A 업무 검수 |
| 조직·업무분장 | 성남시 조직·업무 검색·현행 별표 | 조직 ID·상위 조직·업무·관할·시행일 | A 검수 주도, C 구조화 |
| 복지·혜택 | 복지로 지자체·중앙, 공공서비스 API | 서비스 ID·지역·대상·지원내용·신청·기준일·원문 | C 연계, A 적용 범위 검수 |
| 모델 라벨·평가 | 위 검수 자료와 별도 허용 예시 | 목적·분야·업무·부서 후보·누락 정보·보류 이유 | D 작성, A 공동 검수 |

수집기 산출물에는 `source_id`, `source_url`, `fetched_at`, `published_at`, `updated_at`,
`effective_from`, `effective_until`, `content_hash`, `license`, `training_use_status`,
`review_status`, `reviewer`, `supersedes`를 둔다. 날짜를 모르면 빈 값과 미확인 상태를 남기며,
수집일을 정책 시행일로 채우지 않는다.

구조화 테이블은 `SourceDocument`, `TaxonomyNode`, `TaxonomyMapping`, `OrganizationUnit`,
`WorkAssignment`, `PublicService`, `RequiredInformation`으로 나눈다. 원본 분류와 내부 분류의
대응 관계에는 근거 문서·검수자·유효기간을 함께 기록한다.

HTML은 본문과 표를 중심으로 수집하고 반복 메뉴·푸터는 제거한다. 첨부는 추출 후 원문 표·각주와
대조한다. 필요한 정보가 첨부에만 있는 항목은 목록 수집만으로 완료 처리하지 않는다. 원문과
구조화 결과는 검수 단계에 보관하고, 승인된 데이터만 검색·추천에서 사용한다.

## 5. 추가로 확보할 자료

1. 국민권익위 분류체계의 현행 명세·전체 코드 응답·이용 조건.
2. 성남시 실제 과·팀별 업무분장과 시설·지역 관할, 조직개편 대응 방법.
3. 사용자가 어려움을 느낀 인증 이후 부서 선택 화면의 정확한 경로와 선택 방식.
