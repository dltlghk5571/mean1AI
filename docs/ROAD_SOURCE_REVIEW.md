# 도로·보도 파손 업무 한 건의 공식 근거 검수

2026-09-13 · `G0 → G2 → G2.1` · 검수 기록 `road-review-20260913`

**도로 파손이라는 주제만으로 담당 팀을 확정할 수 없다. 수정구는 도로관리팀과 TF팀의
세부 관할 확인이 필요하고, 분당구는 도로관리팀과 보도관리팀의 업무가 구분돼 있다.**
시민에게 부서를 선택시키지 않고 장소·시설 설명을 받아 담당자가 후보를 검토해야 한다는
설계 근거다. 시민의 실제 사용성이나 업무 절감 효과를 측정한 결과는 아니다.

이번 공개 근거 확인은 `pilot-service-road` 한 건으로 종료한다. 자료 이용 범위·시설 관할·
공식 서식의 검수가 남아 있어 서비스 적용은 `pending`이다. 다른 업무 수집, 분류 모델 평가,
실제 기관 제출이나 운영 자료 승인은 이번 범위에 포함하지 않는다.

## 공식 신고 경로와 확인하지 못한 서식

- **안전신문고:** 행정안전부 안내에 `도로·시설물 파손 및 고장`이 안전신고 대상으로 표시되고,
  앱과 포털을 안내한다. 처리기관은 행정안전부가 지정하는 구조로 설명돼 있다.
  이 표시명을 외부 API의 고정 분류 코드로 사용하지 않는다. [S5](https://www.mois.go.kr/frt/sub/a06/b10/safetyReport/screen.do)
- **성남시 민원상담:** 현재 민원/제안/신고 목록은 민원상담을 국민신문고와 통합 운영되는
  행정기관 민원서비스로 설명한다. 목록에 표시된 소통지원팀을 도로 보수 담당으로 간주하지
  않는다. 조회 때 보인 45건은 이 서비스 목록의 표시 건수이며 성남시 전체 민원 분류 수가
  아니다. [S4](https://www.seongnam.go.kr/pm02020101)
- **서식 확인의 한계:** 안전신문고는 `#/safereport/safereport`로 진입하는 링크를 확인했지만,
  이번 정적 GET에는 작성 서식이 포함되지 않았다. 제목·위치·사진의 필수 여부, 인증·동의,
  접수 응답은 검수하지 못했다. 성남시 목록 역시 빈 신청서 확인을 대신하지 않는다.
  [S6](https://www.safetyreport.go.kr/), [S4](https://www.seongnam.go.kr/pm02020101)

이 페이지들로 외부 시스템의 민원 등록 API·이용 권한·수신 확인 규격을 확인한 것은 아니다.
API가 없다고 단정하지도 않는다. 앱 내부 시연 접수를 공식 접수로 표시하거나 두 경로에
동일 민원을 동시에 보내지 않는다. 실제 연계는 별도 기관 계약과 시민 확인이 필요한 단계다.

## 현재 질문과 자료 후보의 관계

현재 [도로 질문 템플릿](../app/data/citizen_question_templates.json)은 `facility_type`과
`hazard_now`를 묻고, 초안의 `content`·`location_text`는 별도로 관리한다.

| 프로젝트 항목 | 이번 근거로 뒷받침하는 용도 | 한계·설계 기준 |
| --- | --- | --- |
| `location_text` | 어느 구역의 어떤 현장인지 설명 | 공식 주소를 모르면 다른 설명을 받음. 관할 확정 값으로 추정하지 않음 |
| `facility_type` | 차도·보도·자전거길·공원 내부 길 등 후보 구분 | 행정 부서명 대신 시민이 관찰한 시설을 확인 |
| `content` | 파인 곳·들뜬 보도 등 상태와 원하는 도움 확인 | 원문을 보존하고 이미 말한 내용은 다시 묻지 않음 |
| `hazard_now` | 시민이 관찰한 현재 위험 확인 | 기존 `choices_only` 질문. LLM이 안전 상태를 대신 채우지 않음 |
| 사진 | 이미 가진 사진으로 현장 설명 보완 | 우리 앱의 선택 첨부이며 공식 신고서의 필수 사진 요건은 미확인 |

위 항목은 프로젝트의 대화 설계다. 공식 필수 서류·수리기한·보상 기준으로 안내하지 않는다.
안내만 원하는 시민에게 접수용 항목을 모두 요구하지 않고, 접수 준비와 최종 제출 동의를 구분한다.

기존 `seongnam-pilot-20260907-v1`의 `pilot-service-road`는 다섯 업무 후보를 연결하지만,
서비스의 단일 `source_document_id`는 `pilot-source-jungwon`이다. 실제 자료 버전에서는
수정·중원·분당의 근거 관계와 프로젝트 ID/공식 조직 코드 대응을 검수해야 한다.
이번에는 후보 JSON·해시·날짜·검색/학습 승인·질문·운영 배정 자료를 변경하지 않았다.
따라서 기존 `source-review` 결과나 실행 중인 앱에 이 기록이 자동 적용되지는 않는다.
