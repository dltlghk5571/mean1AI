# 도로·보도 파손 업무 한 건의 공식 근거 검수

2026-09-13 · `G0 → G2 → G2.1` · 검수 기록 `road-review-20260913`

**도로 파손이라는 주제만으로 담당 팀을 확정할 수 없다. 수정구는 도로관리팀과 TF팀의
세부 관할 확인이 필요하고, 분당구는 도로관리팀과 보도관리팀의 업무가 구분돼 있다.**

공식 서식의 검수가 남아 있어 서비스 적용은 `pending`이다. 다른 업무 수집, 분류 모델 평가,
실제 기관 제출이나 운영 자료 승인은 이번 범위에 포함하지 않는다.

## 공식 신고 경로와 확인하지 못한 서식

- **안전신문고:** 행정안전부 안내에 `도로·시설물 파손 및 고장`이 안전신고 대상으로 표시되고,
  앱과 포털을 안내한다. 처리기관은 행정안전부가 지정하는 구조로 설명돼 있다.
  이 표시명을 외부 API의 고정 분류 코드로 사용하지 않는다. [S5](https://www.mois.go.kr/frt/sub/a06/b10/safetyReport/screen.do)
- **성남시 민원상담:** 현재 민원/제안/신고 목록은 민원상담을 국민신문고와 통합 운영되는
  행정기관 민원서비스로 설명한다. 목록에 표시된 소통지원팀을 도로 보수 담당으로 간주하지
  않는다. 조회 때 보인 45건은 이 서비스 목록의 표시 건수이며 성남시 전체 민원 분류 수가
  아니다. [S4](https://www.seongnam.go.kr/pm02020101)
- **서식 확인의 한계:** 안전신문고는 `#/safereport/safereport`로 진입하는 링크를 확인했지만,
  이번 정적 GET에는 작성 서식이 포함되지 않았다. 제목·위치·사진의 필수 여부, 인증·동의,
  접수 응답은 검수하지 못했다. 성남시 목록 역시 빈 신청서 확인을 대신하지 않는다.
  [S6](https://www.safetyreport.go.kr/), [S4](https://www.seongnam.go.kr/pm02020101)

이 페이지들로 외부 시스템의 민원 등록 API·이용 권한·수신 확인 규격을 확인한 것은 아니다.
API가 없다고 단정하지도 않는다. 앱 내부 시연 접수를 공식 접수로 표시하거나 두 경로에
동일 민원을 동시에 보내지 않는다. 실제 연계는 별도 기관 계약과 시민 확인이 필요한 단계다.

## 현재 질문과 자료 후보의 관계

현재 [도로 질문 템플릿](../app/data/citizen_question_templates.json)은 `facility_type`과
`hazard_now`를 묻고, 초안의 `content`·`location_text`는 별도로 관리한다.

| 프로젝트 항목 | 이번 근거로 뒷받침하는 용도 | 한계·설계 기준 |
| --- | --- | --- |
| `location_text` | 어느 구역의 어떤 현장인지 설명 | 공식 주소를 모르면 다른 설명을 받음. 관할 확정 값으로 추정하지 않음 |
| `facility_type` | 차도·보도·자전거길·공원 내부 길 등 후보 구분 | 행정 부서명 대신 시민이 관찰한 시설을 확인 |
| `content` | 파인 곳·들뜬 보도 등 상태와 원하는 도움 확인 | 원문을 보존하고 이미 말한 내용은 다시 묻지 않음 |
| `hazard_now` | 시민이 관찰한 현재 위험 확인 | 기존 `choices_only` 질문. LLM이 안전 상태를 대신 채우지 않음 |
| 사진 | 이미 가진 사진으로 현장 설명 보완 | 우리 앱의 선택 첨부이며 공식 신고서의 필수 사진 요건은 미확인 |

위 항목은 프로젝트의 대화 설계다. 공식 필수 서류·수리기한·보상 기준으로 안내하지 않는다.
안내만 원하는 시민에게 접수용 항목을 모두 요구하지 않고, 접수 준비와 최종 제출 동의를 구분한다.

기존 `seongnam-pilot-20260907-v1`의 `pilot-service-road`는 다섯 업무 후보를 연결하지만,
서비스의 단일 `source_document_id`는 `pilot-source-jungwon`이다. 실제 자료 버전에서는
수정·중원·분당의 근거 관계와 프로젝트 ID/공식 조직 코드 대응을 검수해야 한다.
이번에는 후보 JSON·해시·날짜·검색/학습 승인·질문·운영 배정 자료를 변경하지 않았다.
따라서 기존 `source-review` 결과나 실행 중인 앱에 이 기록이 자동 적용되지는 않는다.

### 확인된 사실과 해석

- **B1:** TF팀 업무에 도로 개설뿐 아니라 보도 유지관리·포트홀 긴급 복구도 표시된다.
  그러나 그 업무 행에는 동·노선별 전체 담당 범위가 없다. S1과 업무 종류를 대조할 수는
  있어도 어느 팀이 특정 현장을 최종 처리하는지 확정할 수는 없다.
- **B2, 인쇄 140쪽:** 도로관리TF팀장 표기 아래에 금토동 소로1-31호선, 시흥~사송간,
  사송1통의 개설 사업이 있다. 같은 표의 2025년 실적에는 수진동 3-251호선 사업 완료가
  기록돼 있다. 수진동은 S1의 도로관리팀 유지관리 범위에도 나온다. 이는 **개설 사업의 이력과
  상시 유지관리 관할을 나눠 확인해야 한다**는 해석의 근거이며 현재 TF팀 관할 확대 승인은 아니다.
- **B2, 인쇄 140~142쪽:** 금토동 사업은 실효·재검토 상태와 후속 계획이 함께 적혀 있다.
  계획에 실린 사업이라고 현재 공사 중으로 답하면 안 된다. B2는 사송1통 사업기간을
  2025~2029년으로, B3는 2030년까지 추진하는 사업으로 설명한다. 차이의 사유와 현재 일정은
  확인되지 않아 완료 시점을 선택하거나 시민에게 약속하지 않는다.
- **B3:** 사송1통의 특정 375m 개설 사업과 TF팀 담당 표기를 확인했다. 이 근거를 사송동
  전체의 기존 도로·보도 파손 접수 담당으로 일반화하지 않는다.

| 사송동의 도로에 구멍이 생김 | 정확한 지점·시설과 개설 공사 구간인지 확인이 더 필요 | 사송1통 개설 사업 담당이라는 이유로 TF팀에 자동 배정 |
| 사송1통 도로 개설 사업의 진행을 물음 | B2·B3의 사업 구간과 TF팀 표기를 대조해 문의 후보 준비 | 일반 파손 민원으로 바꾸거나, 계획 연도를 현재 준공일로 확정 |

질문을 늘리기 전에 이미 말한 장소·시설·사업명을 활용한다. 부족할 때만 어떤 지점인지,
기존 길의 파손인지 알려진 개설 사업에 대한 문의인지 확인한다. 시민에게 담당 부서를 알아오라고
요구하지 않는다. 현장 관리기관·이관 상태가 불명확하면 담당자 검토를 유지한다.

### RD02를 확정하기 위해 남은 전달 사항

A·C가 확인할 내용은 다음 세 가지다. 공개 자료에 같은 팀 이름이 더 등장하는 것만으로는
해결되지 않으며, 근거 자료 또는 권한 있는 담당 부서의 확인 기록이 필요하다.

1. 두 팀의 도로·보도 상시 유지관리 동/노선별 범위와 그 기준의 시행일.
2. 개설 공사 중인 구간과 인수인계가 끝난 구간의 파손 민원 담당 전환 기준·이관일.
3. 공원 내부 길·사유지·별도 관리 도로의 예외와 담당 미확정 시 검토 경로.

문의는 발송하지 않았다. 실제 시민 정보·개인 연락처를 모을 필요 없이 위 업무 기준만 확인한다.
추가 자료가 오기 전까지 같은 검색을 반복하거나 RD02를 해결로 표시하지 않는다.

## 미해결 항목과 팀 전달

자료 이용 범위는 [기존 검수표](SEONGNAM_DATA_REVIEW.md)의 R01을 따른다. 공식 페이지를
읽었다는 사실만으로 개별 자료의 검색·학습을 허용하지 않으며 `unknown` 상태를 유지한다.

| ID | 다음 확인 | 담당 | 해결 증거 |
| --- | --- | --- | --- |
| RD01 · 보류 | 사용할 자료별 검색·학습 이용 범위 | A 기획/데이터 | 자료별 이용 표시 또는 허락 근거·확인일. 일반 정책만으로 일괄 승인하지 않음 |
| RD02 · 공개 대조 완료, 관할 미확정 | 수정구 두 팀의 동·시설 경계, 공사/유지관리·인수인계 기준, 공원 내부·사유지·별도 관리 도로 예외 | A, C | 위 B1~B3의 한계를 보완할 공식 관할 자료 또는 담당 부서 확인 기록. 미확정 유지 |
| RD03 · 미확인 | 실제 빈 신고서의 필수/선택 항목·첨부·인증·동의, 외부 연계 가능 범위 | A, 연계 시 C | 권한 있는 팀원의 서식 검수표와 연계가 있다면 기관 문서. 개인·인증값 제외 |
| RD04 · 미확인 | 업무 시행·변경 시점, 사업기간 표기 차이와 적용 직전 공식 링크 유효성 | A | 날짜의 의미를 구분한 공식 근거·재확인 기록. 화면 수정일·조회일로 시행일을 채우지 않음 |

공개 자료로 할 수 있는 이번 RD02 대조는 여기서 종료한다. 실제 관할 확정은 추가 근거와
A·C 검토 대기다. [TASKS](../TASKS.md)에 그 의존성을 남기고, 서버 없이 가능한 G3.1의
LLR-02 입력 상태 대조로 다음 우선순위를 돌린다. 실제 자료 적용·승인 상태는 바뀌지 않았다.
