# 시민 화면 읽기·키보드 개선

AI 서버나 외부 서비스 없이 홈·챗봇·직접 작성·접수 확인서·민원 조회·추가 문의를 더 쉽게
읽고 조작하기 위한 UI 개선이다. 실제 보조기기 사용자 평가와 접근성 적합성 인증은 별도 작업이다.

## 글자 크기

시민 화면 위쪽의 `글자 크기`에서 기본(100%)·크게(150%)·아주 크게(200%)를 선택한다.
네이티브 라디오 버튼을 사용하므로 Tab으로 이동하고 방향키로 크기를 바꿀 수 있다.
글자와 입력칸·사진 안내·추가 문의의 글꼴 크기를 상대 단위로 바꾸고, 화면 폭에 따라 변하는
큰 제목도 같은 비율로 확대한다. 확대 시 메뉴·버튼·카드는 줄을 바꾸며, 좁은 화면의 본문은
한 열로 표시한다. 브라우저 자체 확대나 기본 글꼴 설정도 막지 않는다.

저장되는 것은 `localStorage`의 `seongnam.citizen.text-size.v1` 한 항목이며 값은
`standard`, `large`, `extra` 중 하나다. 대화·민원·사진·세션·조회 코드는 저장하지 않는다.
설정은 같은 브라우저·같은 사이트의 시민 페이지 사이에 유지되고, 기본 선택으로 되돌릴 수 있다.
브라우저가 저장을 막으면 현재 화면에만 적용하며 이를 안내한다. 알 수 없는 저장 값은 기본으로
처리한다. JavaScript가 꺼져 있어도 기존 화면과 브라우저 확대는 사용할 수 있으며,
사이트 자체 크기 선택기는 표시하지 않는다. 담당자 페이지에는 시민 설정을 적용하지 않는다.

## 대화 입력과 포커스

- 메시지는 글자로 표시한 `보내기` 버튼 또는 Ctrl+Enter(Mac은 ⌘+Enter)로 전송한다.
  Enter와 Shift+Enter는 줄바꿈이다. 한국어 조합 중인 키 이벤트는 전송에서 제외한다.
  실제 기기별 한글 IME 조합 동작은 추가 검증이 필요하다.
- `최근 대화 보기`로 마지막 메시지에 이동할 수 있다. 대화 영역 자체도 Tab으로 접근해
  키보드로 스크롤할 수 있다. 새로운 응답은 별도의 상태 영역에서 안내한다.
- 일반적인 전송 후에는 입력칸으로 돌아가며, 접수 요약 단계에서는 확인 제목으로 이동한다.
  응답을 기다리며 사용자가 다른 활성 요소로 이동했다면 포커스를 강제로 가져오지 않는다.
- 서버 오류는 오류 안내로 포커스를 옮기고 입력을 보존한다. 요약 수정 오류는 해당 입력칸의
  `aria-invalid` 및 연결된 설명에도 표시한다. 접수·조회 양식은 입력칸 이름과 도움말을 구분한다.
- 새 대화 확인창에는 제목·설명 연결과 취소 버튼의 초기 포커스를 둔다. Esc 또는 취소 후에는
  새 대화 버튼으로 돌아간다. 취소 시 작성하던 서버 대화와 접수 초안을 초기화하지 않는다.
- 기존 동의·재시도·접수 권한은 유지한다. 글자 크기 변경 자체는 민원을 저장하거나 전송하지 않는다.

## 확인 기준과 후속 검증

확대 시 내용·기능을 잃지 않는지 보는 기준은
[W3C의 글자 확대 설명](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)을 참고했다.
좁은 화면에서 본문이 다시 배치되는지와 키보드 이동 순서는
[Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html),
[Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)를 참고했다.
이 설명 문서들은 개선 방향을 정하는 근거이며 이 구현 전체의 적합성 판정은 아니다.

로컬 브라우저에서 글자 크기 전환·페이지 이동/새로고침 후 유지, 320px 확대 배치,
키보드 대화 전송·확인·접수, 수정 오류·조회 실패 안내, 최근 대화 이동·확인창 취소를 검증한다.
구체적인 결과는 [UI 검증 기록](UI.md)에 남긴다. 이 작업은 서버 로직·DB·의존성을 추가하지 않는다.

다음은 실제 대상 사용자와 확인할 항목이다.

1. 고령 사용자 등에게 기본·150%·200% 화면을 보여 주고 접수·조회 과제의 성공률과 어려운 문구를 기록한다.
2. NVDA·VoiceOver·TalkBack에서 새 답변 낭독, 오류 설명, 사진 선택기와 확인창을 확인한다.
3. 다양한 모바일 브라우저의 한글 입력기, 사용자 글꼴·고대비·확대 설정과 기기별 조작을 확인한다.
4. 긴 안내 자료·다수 문의·사진이 있는 실제 길이의 합성 예시로 색 대비·재배치·키보드 흐름을 추가 평가한다.
