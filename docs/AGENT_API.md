# 시민 에이전트 도구 계약 v2

2026-09-06 · `app/agent_schemas.py`, `app/services/citizen_agent.py`

대화 모델은 다음 행동을 JSON으로 제안하고, 앱 서버가 도구·단계·근거를 검증해 실행한다.
현재 기본값 `CHAT_PROVIDER=agent_demo`는 같은 계약으로 움직이는 시연 제공자다.
실제 LLM·동아리 서버·네트워크 전송은 아직 없다. 시민의 목적은 버튼으로 확인하며 자유 입력을
키워드로 의도 분류하지 않는다. 접수 후 분류기는 기존 `AI_PROVIDER`와 별도다.

## 실행 흐름

시민 메시지 → 서버 상태 준비·비식별화 → `AgentPlanner.plan(PlanningContext)` →
읽기 도구 실행 → 결과를 모델에 전달 → 질문/자료 안내/요약 확인 → 시민에게 표시한다.

한 시민 요청에서 모델 호출은 최대 4회, 도구 실행은 최대 3회다. 마지막 호출은 종료 행동이어야
한다. 반복 call ID와 예산 초과는 실패한다. 도구 목록에 URL 조회·SQL·접수·승인·종결은 없다.
모델은 서버 초안이나 대화 단계를 수정할 수 없다.

`PlanningContext`는 `schema_version=2`, `stage`, 비식별 `draft`와 `messages`, 이전 도구
결과인 `observations`, `remaining_tool_calls`를 가진다. 매번 깊은 복사본을 주며 세션·쿠키·
CSRF·조회 코드·소유자 ID·내부 민원 기록을 제공하지 않는다.

## 도구 제안 JSON

```json
{
  "kind": "tool",
  "call": {
    "name": "search_services",
    "call_id": "search_1",
    "query": "가로등",
    "limit": 3
  }
}
```

`query`는 최대 2,000자, `limit`는 1~3이다. 현재 검색은 검수한 제목·설명의 어휘 일치 기준선이며
LLM 분류나 임베딩 검색이 아니다. 한국어 활용형·복합 질문의 재현율은 후속 개선 대상이다.
빈 검색어는 유효한 자료 중 최대 3개를 안내한다. 다른 시민의 민원은 검색 대상이 아니다.

```json
{
  "kind": "tool",
  "call": {
    "name": "get_required_information",
    "call_id": "requirements_1",
    "service_id": "DEMO-LIGHT"
  }
}
```

service ID는 **같은 요청에서 검색으로 돌려받은 ID**만 허용한다. 생략하거나 null이면 공통
내용·장소 질문을 반환한다. 결과 예시:

```json
{
  "call_id": "requirements_1",
  "name": "get_required_information",
  "services": [],
  "required_information": [
    {"field_id": "location_text", "question": "어느 장소인지 주변 시설 이름을 알려 주세요.", "required": false}
  ],
  "catalog_available": true
}
```

검색 결과의 `services`에는 서버가 만든 ServiceCard가 들어간다. ID·제목·검수한 설명·
출처 URL/제목·카탈로그 버전·재검토 기한·합성 여부·사람 검토 필요 여부를 가진다.
모델이 생성한 URL이나 설명을 시민에게 직접 표시하지 않는다.

## 종료 행동

| JSON | 서버 검사·결과 |
| --- | --- |
| `{"kind":"ask","field_id":"content"}` | description 단계, 등록된 내용 질문 |
| `{"kind":"ask","field_id":"location_text"}` | location 단계, 등록된 장소 질문 |
| `{"kind":"answer","service_ids":["DEMO-LIGHT"]}` | information 단계, 이 요청에서 검색한 자료만 최대 3개 |
| `{"kind":"review"}` | review 단계, 시민에게 서버 초안 확인 요청 |
| `{"kind":"clarify"}` | intent 단계, 정보 안내/민원 접수 목적 선택 |

필드 추가·임의 문장·존재하지 않는 ID·다른 단계의 행동은 거부한다. 필요한 항목에 `photo` 등을
등록하더라도 현재 UI에서 질문하거나 저장하지 않는다. 동적 질문과 첨부 계약은 추후 추가한다.

최종 접수는 이 JSON에 없다. 시민이 접수 요약을 확인하고 동의한 `confirm` 요청만 기존
[시민 API](CHAT_API.md)를 통해 접수한다. 복지 자격·과태료·허가 등 최종 판단은 담당자에게 남긴다.

## 출처·일관성·실패

- 승인되고 재검토 기한과 서비스 유효기간을 만족하는 스냅샷만 도구가 읽는다.
- 한 요청은 하나의 승인 이력에 고정된다. 저장 직전 승인 상태가 변경·만료·철회됐으면
  결과를 버리고 대화 상태를 롤백한다. 이 검사는 현재 SQLite 쓰기 잠금과 함께 수행한다.
- 대화 이어보기에서도 공개 여부를 다시 확인해 철회·만료·교체된 자료 카드를 제외한다.
  이미 열린 화면을 원격으로 지우지는 않으며 다음 요청/새로고침 때 적용한다.
- 합성 자료는 화면에서 시연용으로 표시한다. 검색 실패는 공식 안내 사이트 링크를 제공하며
  해당 링크를 검색된 근거 문서라고 표시하지 않는다.
- 도구 실패·잘못된 JSON·예산 초과는 일반화된 503으로 반환한다. 입력값과 내부 오류를
  응답·로그에 반사하지 않으며 다른 제공자의 성공 응답으로 대체하지 않는다.
- 도구 ID·종류·자료 버전·결과 ID·상태를 `CitizenChatAuditEvent`에 남긴다. 검색어·본문·
  모델의 비공개 추론은 남기지 않는다. 실패/경합으로 버린 실행도 시도·중단 이력을 남긴다.

화면은 카드 내용을 textContent로 표시하고 출처 링크는 서버의 허용된 HTTPS 주소만 쓴다.
스키마·해시·도구 제한이 원문 정확성이나 모든 지시문 공격을 보장하지 않으므로 검수와 평가가 필요하다.

## 동아리 서버 연결 시 할 일

`AgentPlanner.plan` 구현을 서버 어댑터로 교체한다. `PlanningContext.model_json_schema()`와
`STEP_ADAPTER.json_schema()`를 요청·응답 명세로 공유한다. v1 응답 제공자는 `CHAT_PROVIDER=demo`
또는 `unavailable`로 계속 사용할 수 있다. 실제 연결에는 코드 변경이 필요하며 URL만 넣어서는 동작하지 않는다.

1. 모델 ID·인증 방식·서버 주소·구조화 출력 예시를 합의한다. 비밀값은 서버 환경변수로 관리한다.
2. HTTP timeout·전체 요청 기한·취소·동시 실행 제한을 어댑터에 구현한다. 현재 제한은 호출 횟수로,
   임의의 동기 제공자가 멈추지 않는 문제를 실행기가 강제로 중단하지는 못한다.
3. 자유 입력 목적 분류·정보 추출 제안 계약을 추가하고, 서버가 기존 단계와 사용자 확인을 검증한다.
4. LLM 분류기는 별도 어댑터로 연결하고 실재하는 분류·업무·관할 ID를 검증한다.
5. 정상·범위 밖·잘못된 도구·누락 정보·위험·개인정보·중복 요청·서버 장애 고정 평가를 통과한다.

현재 자동 검증은 미검수 자료 제외, 출처 ID 위조, 금지 도구, 호출 예산, 컨텍스트 격리,
철회 중인 답변 저장 차단, 질문→요약→시민 확인 접수와 기존 권한·동시성 검사를 포함한다.
