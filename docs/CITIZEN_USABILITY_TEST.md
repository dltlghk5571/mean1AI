# 시민 사용성·보조기기 검증 가이드

AI 서버를 기다리지 않고 4명이 진행할 수 있는 수동 검증 절차다. `AI_PROVIDER=rules`,
`CHAT_PROVIDER=demo` 또는 `agent_demo`와 별도 로컬 DB를 사용한다. 실제 민원·신상정보 대신
아래 합성 과제를 사용하며, 이 문서의 미실시 항목을 통과 결과로 발표하지 않는다.

## 준비와 역할

실행 방법은 [README](../README.md)의 로컬 실행을 따른다. 기기마다 접속 가능한 승인된
개발 환경을 준비하고 외부에 데모를 공개하지 않는다. 휴대전화에서 PC의 `127.0.0.1`로
접속할 수 있다고 가정하지 않는다. 운영체제·브라우저 설정을 바꿨다면 시험 후 원래대로 돌린다.

| 역할 | 이번 검증에서 할 일 |
| --- | --- |
| A · 기획/데이터 | 합성 과제 설명, 참여자 관찰, 도움 요청·막힌 문구 기록 |
| B · 시민 UI | 키보드·확대·보조기기 검사, 발견한 UI 문제 수정 |
| C · 서버/연계 | 별도 DB·데모 모드 준비, 접수 한 건·조회 권한·저장 결과 확인 |
| D · 모델/평가 | AI 없이도 평가 가능한 과제 성공·시간·오류 결과 정리, B의 수정 재확인 |

참여자에게는 장애·질병 등 민감 정보를 요구하지 않는다. 참여자는 중단할 수 있으며,
별도 동의 없이 음성·화면·개인정보를 기록하지 않는다. 테스트 사진은 단색 도형처럼
직접 만든 합성 이미지로 준비한다. 얼굴·차량번호·실제 촬영 위치가 있는 사진은 사용하지 않는다.

## 시민에게 제시할 과제

조작 방법을 먼저 가르치지 않고 목적만 설명한다. 도움을 요청하면 안내하되, 자력 완료와
도움을 받은 완료를 구분해 적는다. 읽는 속도나 도움 요청으로 참여자에게 점수를 매기지 않는다.

| 과제 | 상황과 목표 | 확인할 결과 |
| --- | --- | --- |
| U1 · 시작 | “가상 시연 공원 앞 보도블록이 들떠 있어요.” 내용을 전할 곳을 찾는다. | 부서 선택 없이 대화에 진입하고 민원 접수 의사를 선택 |
| U2 · 읽기/수정 | 글자를 키우고, 장소를 “가상 시연 공원 정문”으로 정리한다. | 선택 상태를 알고 제목·장소·내용을 확인·수정 |
| U3 · 사진/접수 | 합성 사진 3장을 추가하고 1장을 삭제한 뒤 접수한다. | 사진 2장·동의·접수번호 확인; 사진 선택만으로 접수되지 않음 |
| U4 · 다시 찾기 | 내 민원에서 접수한 내용과 사진을 다시 확인한다. | 본인 민원을 찾아 공개 답변 여부를 이해 |
| U5 · 이어 묻기 | “확인 일정이 궁금해요.”를 기존 민원에 남긴다. | 새 접수 대신 추가 문의 한 건을 저장하고 답변 대기 확인 |
| U6 · 오류 복구 | 직접 작성 화면에서 제목을 비우고 다음 단계로 진행한다. | 오류를 알아차리고 값을 수정해 계속 진행 |

사용성이 어려운 시민 5~8명부터 확인한다는 것은 모집 계획이며 현재 참여자 수가 아니다.
과제별 자력 완료/도움 후 완료/미완료, 소요시간, 도움 요청 횟수, 막힌 문구를 기록한다.
사용성 개선 수치는 실제 비교 과제를 수행하기 전까지 산출하거나 주장하지 않는다.

## 기기별 조작 검사

| 번호 | 환경·조작 | 기대 동작 | 현재 검증 범위 |
| --- | --- | --- | --- |
| K1 | 마우스를 내려놓고 Tab·Shift+Tab·방향키·Enter·Space 사용 | 본문 바로가기, 글자 크기 선택, 입력·수정·동의·접수 가능 | 로컬 브라우저 부분 확인 |
| K2 | 사진 3장 선택 → Enter로 1장 삭제 | 선택 직후 첫 삭제 버튼, 삭제 후 사진 추가 입력에 포커스 | 로컬 확인 |
| K3 | 새 대화 창 → Escape, 오류 발생 → 수정 | 취소 후 원래 버튼, 오류 안내와 입력 위치를 찾을 수 있음 | 로컬 확인 |
| S1 | Windows + NVDA, 읽기 탐색과 양식 입력으로 U1~U5 | 제목·입력 이름·선택 상태를 이해하고 새 답변을 알 수 있음 | 미실시 |
| S2 | iOS + VoiceOver, Android + TalkBack으로 U1~U5 | 탐색 순서·사진 선택·오류 설명·접수 결과를 이해 | 미실시 |
| I1 | 실제 한글 입력기로 조합 중 Enter, 조합 완료 후 Enter | 조합 중 메시지가 전송되지 않으며, 일반 Enter는 줄바꿈 | 실기기 미실시 |
| I2 | Ctrl+Enter / Mac의 ⌘+Enter와 보내기 버튼 | 작성한 메시지가 한 번만 전송되고 다음 입력/확인으로 이동 | Ctrl+Enter 로컬 확인, Mac 실기기 미실시 |
| C1 | Windows 대비 테마의 밝은/어두운 팔레트 | 선택 라디오·버튼 경계·초점·비활성 상태·현재 단계 식별 | CSS 대응 구현, 실기기 미실시 |
| C2 | 브라우저 기본 글꼴 변경·200% 확대·동작 줄이기 | 글자가 잘리지 않고 필요한 기능 접근, 과도한 스크롤 애니메이션 없음 | 사이트 글자 확대 로컬 확인, 나머지 미실시 |
| P1 | localStorage만 차단하고 시민 세션 쿠키는 허용한 테스트 환경 | 현재 페이지 글자 변경 가능, 저장 불가 안내, 접수 동작 유지 | 미실시 |

스크린리더는 새 답변·오류를 사용자가 알아차리는지, 동일 내용을 불필요하게 반복 낭독하는지
확인한다. 접근성 트리에 이름이 존재한다는 사실만으로 실제 낭독 시험을 통과 처리하지 않는다.
보조기기 종류·버전과 기기 설정 차이도 기록한다. 설치나 설정 절차가 다르면 해당 제품의
현행 도움말을 확인하고, 실제로 사용한 설정만 결과에 적는다.

## 긴 내용·사진 경계

짧은 시민 과제를 먼저 진행한 뒤 개발팀이 별도로 확인한다.

- 대화 본문 4,000자, 제목 200자, 장소 300자: 합성 문장과 공백 없는 합성 시설명을 사용한다.
- 사진 최대 3장: 키보드 선택·삭제·동의 해제·재확인·접수 후 표시를 확인한다.
- 추가 문의 2,000자: 저장 후 본문·다음 조작·포커스가 유지되는지 확인한다.
- 320px와 1280px에서 기본·150%·200%로 보고, 가로 넘침·잘림·읽을 수 없는 오류가 있는지 확인한다.
- 초안 새로고침 시 대화는 이어지지만 선택한 사진은 지워지는 현재 정책을 사용자가 이해하는지 본다.

## 결과 기록 양식

아래 블록을 복사한다. 확인하지 않은 항목은 `미실시`로 둔다. 민원 조회 코드, 쿠키,
세션 값이나 실제 사용자 정보는 결과·GitHub Issue·스크린샷에 넣지 않는다.

```text
검증일 / 커밋:
검증자 역할 / 익명 참여자 번호(선택):
기기 / OS / 브라우저 / 보조기기와 버전:
화면 크기 / 글자 크기 / 대비·저장 설정:
과제 번호:
결과: 자력 완료 / 도움 후 완료 / 미완료 / 미실시
소요시간 / 도움 요청 횟수:
재현 순서:
기대 동작 / 관찰한 동작:
합성 자료 여부 / 개인정보를 제외한 증거:
수정 담당 / 재확인 결과:
```

접수를 완료할 수 없음, 다른 사람 기록 노출, 예기치 않은 전송, 키보드 탈출 불가처럼
과제를 막는 문제는 우선 수정하고 해당 과제를 다시 확인한다. 다른 환경에서 통과한 결과로
실패 환경의 결과를 대체하지 않는다. 실제 확인 기록은 [UI 검증 기록](UI.md)에 남긴다.
